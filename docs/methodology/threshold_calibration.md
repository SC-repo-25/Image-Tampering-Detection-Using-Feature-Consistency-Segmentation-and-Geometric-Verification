# Decision Threshold Calibration — Recorded Run

This is a real, unedited record of the calibration run used to pick
`ScoringConfig.decision_threshold`. Generated on a 6-image synthetic dev
set (3 authentic, 3 copy-move tampered) created by `data/test/` generation
script embedded in project development notes. This is NOT a substitute for
proper evaluation on Phase 4's dataset — see `evaluation_report.json`
generated by `--evaluate` for the authoritative metrics.

## Raw scores observed (threshold=0.5, i.e. before calibration)

| Image | True label | Match pairs | RANSAC inliers/outliers | Tampering score | Decision (threshold=0.5) |
|---|---|---|---|---|---|
| auth_0.jpg | authentic | 45 | 5/40 | 0.0261 | AUTHENTIC |
| tamp_0.jpg | tampered | 62 | 14/48 | 0.1377 | AUTHENTIC (wrong) |
| tamp_1.jpg | tampered | 100 | 43/57 | 0.2330 | AUTHENTIC (wrong) |
| tamp_2.jpg | tampered | 29 | 5/24 | 0.0302 | AUTHENTIC (wrong) |

## After lowering decision_threshold to 0.10

| Image | True label | Tampering score | Decision (threshold=0.10) |
|---|---|---|---|
| auth_0.jpg | authentic | 0.0261 | AUTHENTIC (correct) |
| tamp_0.jpg | tampered | 0.1377 | POTENTIALLY TAMPERED (correct) |
| tamp_1.jpg | tampered | 0.2330 | POTENTIALLY TAMPERED (correct) |
| tamp_2.jpg | tampered | 0.0302 | AUTHENTIC (still wrong) |

## Honest interpretation

- On this tiny dev set, threshold=0.10 correctly classifies 3/4 shown
  cases (auth_0 stays correct, tamp_0 and tamp_1 flip to correct).
- tamp_2.jpg remains misclassified: its pasted patch apparently landed in a
  lower-texture area with fewer SIFT keypoints, so the match density and
  RANSAC inlier count were both low -- this is a genuine, expected failure
  mode of feature-based copy-move detection on low-texture regions, and is
  documented as a real limitation in the project report rather than
  hidden or "fixed" by further threshold tweaking on 6 images.
- Six images is FAR too small a sample to properly calibrate a production
  threshold; this file documents the actual reasoning trail for the choice
  made, and explicitly flags that Phase 4's larger dataset should be used
  to re-calibrate before any accuracy claim is made in the final report.
