## 2. Introduction
Digital images are trivially editable, and manipulated images routinely
circulate as if authentic. This project builds a classical (non-deep-
learning) Computer Vision pipeline that analyzes a single image for
internal evidence of copy-move manipulation, using feature matching,
segmentation, and geometric verification — every stage of which is
mathematically transparent and explainable.

## 5. Functional Requirements
1. Accept a single image via CLI and validate it.
2. Preprocess (resize, denoise, grayscale).
3. Extract SIFT features and self-match to find copy-move candidates.
4. Geometrically verify candidates via RANSAC.
5. Localize suspicious regions via segmentation restricted to verified evidence.
6. Fuse evidence into one transparent tampering score and decision.
7. Save visual and JSON reports.
8. Support batch evaluation with real classification metrics.

## 9. Design Decisions & Rationale

**Why segmentation runs after (not before) geometric verification:**
An earlier version built the candidate mask from raw, pre-RANSAC matches.
Real testing (documented in `docs/methodology/threshold_calibration.md`)
showed this over-flagged up to 53% of pixels on a repetitive-texture test
image, because self-matching alone cannot distinguish genuine copy-move
duplication from coincidentally similar unrelated patches. RANSAC's
purpose is exactly to reject such coincidental matches, so localization
was redesigned to consume only RANSAC-inlier point pairs — reducing the
flagged area to ~30% on the same test image and producing more legitimate
localization.

**Why a transparent weighted sum, not a trained classifier, for scoring:**
A trained classifier requires a labeled dataset and a defensible train/
test split to avoid overfitting claims. The project's academic requirement
is explainability — every score must be justifiable in viva down to the
formula. See `src/tampering_score.py` docstring for full weight rationale.

**Why SIFT over ORB/Harris alone:** see `src/feature_extraction.py`
module docstring.

**Why Felzenszwalb over K-Means/MRF/Graph Cut with complex energy terms:**
see Phase 0 feasibility analysis — best balance of segmentation quality
and implementation complexity for a semester project.

## 16. Challenges Faced
- Initial localization mask over-flagged large image areas on repetitive-
  texture content (see Design Decisions, §9) — resolved by restricting
  localization to RANSAC-verified matches only.
- Default decision threshold (0.5) classified every dev-set image as
  AUTHENTIC — resolved via documented, honest recalibration (see
  `docs/methodology/threshold_calibration.md`), which also surfaced a
  genuine remaining false negative (tamp_2.jpg) rather than hiding it.
- Synthetic flat-color test images produce far fewer usable SIFT keypoints
  than real photographs (keypoints concentrate at shape boundaries only),
  which limits how strong a synthetic demo can be — a real dataset (§13)
  is needed for a fully convincing demonstration.
